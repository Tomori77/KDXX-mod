# 口袋修仙 · 模组面板制作指南（天神面板实现）

> 面向想照着做的人。讲清楚「天神面板」这类**游戏内系统面板**用到了哪些东西、怎么搭、有哪些坑。
> 环境：ModSDK `0.1.9f3`（`modApiVersion 2`），游戏 Demo `4777710`。示例工程 `God-panel/`。

---

## 0. 一句话原理

用 `scripts@1` 的**自定义弹窗**（`ui.entry: "menu"` + `panel.view`）做一个挂在系统「模组界面」的面板，脚本同步返回控件树，游戏渲染；点按钮触发 `uiSubmitted`，脚本据此发放灵石/道具。

## 1. 能用 / 不能用（先认清边界）

| 能做 | 不能做 |
| --- | --- |
| 系统「模组界面」全局入口打开 | 改官方设置菜单 |
| 查看状态（境界/灵石/游戏日） | 改修为、境界、属性 |
| 发放灵石（`spiritStones`，±1,000,000） | 伪造战斗胜利、生成敌人 |
| 发放道具（`giveItem`，1–32/次） | 发别包道具、隐藏道具 |
| 回收道具（`takeInventoryItem`） | 任意 HTML/CSS/DOM、网络、DLL |
| 声明式控件（文本/下拉/数量/按钮/翻页…） | 热加载（须完全重启） |

## 2. 硬性要求

- `modApiVersion: 2`。
- manifest 里 **`scripts` 必须同时声明 `maps`**（否则报 `SCRIPTS_REQUIRES_API_V2_AND_MAPS`）。系统面板本身不需要地图内容，但必须有一个同包地图作**锚点**：
  ```json
  {
    "id": "com.you.panel",
    "version": "1.0.0",
    "modApiVersion": 2,
    "enabled": true,
    "domains": {
      "maps": { "schemaVersion": 1, "path": "maps" },
      "scripts": { "schemaVersion": 1, "path": "scripts" }
    }
  }
  ```
- 锚点地图最小写法（可引用官方背景，省得做图）：
  ```json
  {
    "mapId": "com.you.panel:anchor",
    "displayName": "锚点",
    "officialBackgroundMapId": "map_05",
    "startNodeId": "return",
    "entrance": { "mapId": "map_01", "nodeId": "node_tmp_path", "x": 0.2, "y": 0.05 },
    "travelDaysPerEdge": 1,
    "nodes": [
      { "id": "return", "kind": "site", "name": "返回", "x": 0.2, "y": 0.5 },
      { "id": "altar",  "kind": "site", "name": "法坛", "x": 0.6, "y": 0.4 }
    ],
    "edges": [{ "from": "return", "to": "altar" }]
  }
  ```
  入口坐标必须落在官方公开地图的现有节点上（这里是 `map_01` 的 `node_tmp_path`）。

## 4. 面板定义 `scripts/panel.json`

```json
{
  "id": "com.you.panel:panel",
  "name": "面板",
  "mapId": "com.you.panel:anchor",
  "nodeId": "altar",
  "stateVersion": 1,
  "entry": "code/panel.js",
  "events": ["interact", "uiSubmitted"],
  "ui": { "entry": "menu", "label": "天神面板" }
}
```

- `ui.entry`：`menu`＝角色界面「模组界面」全局入口；`node`＝仅绑定节点。
- 含 `view` 的面板必须走 `uiSubmitted`，因此 `events` 必含它。

## 5. 控件速查（本项目用到的）

`panel.view = { version: 1, root: "<根节点id>", nodes: [...] }`，`nodes` 是**扁平树**，父子用 `children` 以 id 引用。

| type | 关键字段 | 用途 |
| --- | --- | --- |
| `column` / `row` | `children` | 纵向 / 横向排列 |
| `grid` | `columns`(1–4), `children` | 网格 |
| `scroll` | `height`(80–500), `children` | 滚动区 |
| `pages` | `children`, `labels`(≤12) | 多页签 |
| `text` | `text`(≤4000) | 纯文本 |
| `button` | `label`, `optionId` | 必须引用 `panel.options` 里的选项 id |
| `select` | `label`, `initial`, `choices[{value,label}]`(≤32) | 下拉；**value 必须以字母开头** |
| `quantity` | `label`, `initial`, `min`, `max`(0–1e6) | 整数数量 |
| `input` | `label`, `initial`, `maxLength`, `required` | 文本输入 |
| `list` | `items[]`(≤100) | 列表 |
| 通用 `style` | `color/background` 仅 `#RRGGBB`；`gap/padding`≤32；`width` 40–1000 | 样式 |

限额：每文档 ≤128 控件、≤8 层、≤32 表单字段；输出 ≤64 KiB。

`panel.options` ≤6 条，每条 `{ id, label, disabledReason? }`。**底部固定操作栏**由它渲染，按钮通过 `optionId` 引用。

## 6. handler 写法（关键！）

```js
function handle({ event, state, world }) {
  var v = { ...state.variables };
  var effects = [];
  var notice = v.notice || "…";

  // 只有 uiSubmitted 才有 event.values
  var vals = (event.type === "uiSubmitted") ? (event.values || {}) : {};
  var option = event.type === "uiSubmitted" ? event.optionId : "";

  if (option === "grant") {
    // 表单值以【控件 id】为键，不是标签！
    var raw = vals.pick;          // 对应 { id:"pick", type:"select" }
    var count = Number(vals.count); // 对应 { id:"count", type:"quantity" }
    if (count > 32) count = 32;
    effects.push({ type: "giveItem", templateNumericId: idOf(raw), count: count });
  }

  v.notice = notice;
  return {
    ...state,               // 保留 tasks/gates/timers/panel（省略会清空）
    variables: v,
    effects: effects,
    panel: { title: "…", body: notice, options: [...], view: {...} }
  };
}
```

**必须记住的两条**：

1. `event.values` 以**控件 `id`** 为键。控件 `id` 与你在脚本里用的变量名无关。写 `{ id: "tabs", type: "select" }` 就必须读 `vals.tabs`。
2. `select.choices[].value` 与 `initial` 必须是**字母开头的字符串**（正则 `^[a-zA-Z][a-zA-Z0-9_-]{0,63}$`）。数字 ID 要编码，例如 `"i300001"`，脚本里再解码回数字。

## 7. 效果与限额

```js
// 灵石
effects.push({ type: "spiritStones", amount: 1000 });   // ±1,000,000
// 发道具
effects.push({ type: "giveItem", templateNumericId: 300001, count: 3 }); // count 1–32
// 收道具
effects.push({ type: "takeInventoryItem", templateNumericId: 300001, count: 1 });
```

- 每次事务 `effects` ≤16 条；**道具合计 ≤32 件**；任一步失败则整笔回滚。
- `giveItem` 只接受**官方已发布且可获取**（`isPublished && isObtainable`）或**同包**道具；别包/隐藏道具不行。
- 带 `uniquePerSave` 的道具受唯一性约束，已有则可能不再给。

## 8. 数据来源：内置官方道具目录

脚本**没有文件系统**，所有数据必须**内联进 JS**。官方目录在 SDK：
`reference/domains/items/base-item-public-catalog.json`

- 全部 2002 件；可发放（`isPublished && isObtainable`）**1718** 件；带 `uniquePerSave` 69 件。
- 用生成脚本把「分类 → [numericId, name]」抽出来，序列化成 JS 里的 `DATA`，再写 handle。示例分类计数：

| 分类 | 数量 | 分类 | 数量 |
| --- | ---: | --- | ---: |
| 法器 | 856 | 配方 | 103 |
| 材料 | 246 | 储物袋 | 62 |
| 招式 | 182 | 符箓 | 56 |
| 丹药 | 106 | 投掷物 | 44 |
| 功法 | 28 | 占卜 | 25 |
| 宝箱 | 10 | 阵法 | 0 |

生成脚本（示意，Node/其它语言均可）：

```js
const cat = JSON.parse(fs.readFileSync(CATALOG, 'utf8'));
const byCat = {};
for (const it of cat.items) {
  if (!it.isPublished || !it.isObtainable) continue;
  (byCat[it.category] ??= []).push([it.numericId, it.name]);
}
const JS = 'var CATEGORIES=[["all","全部"],["pill","丹药"],...];'
         + 'var DATA=' + JSON.stringify(byCat) + ';'
         + '<handle 源码>';
fs.writeFileSync('code/panel.js', JS);
```

## 9. 交互设计：分类 / 搜索 / 分页（天神面板做法）

- 状态存 `variables`：`cat`（当前分类）、`q`（搜索词）、`page`（页码）、`notice`。
- 每次提交后按 `cat + q` 过滤，每页 24 件，用 `slice` 取当前页，塞进 `select.choices`。
- 搜索匹配「名称 **或** 数字编号」包含关键字；选择项标签可带编号 `名字 #100001`。
- 「分类」用 `select`（值如 `all/pill/implement/...`）；「上一页/下一页/搜索/发放/清空」用 `button`。

## 10. 调试与踩坑

- **分类/选择不生效、被重置**：八成是 `event.values` 的键写错了（用了标签而非控件 id）。
- **发道具提示未选中**：同上，读的键不对。
- `select` 的 `initial` 必须存在于 `choices` 且以字母开头，否则界面校验报「选项无效」。
- 表单字段必须**完整提交**（所有 input/select/quantity 都要有值），缺字段会被拒。
- 脚本必须**同步**返回普通 JSON；无 `async`、无 `import/require`、无 `fetch`、无 `Date`。
- 输出 ≤64 KiB，代码 ≤256 KiB；每包/会话 ≤16 个脚本定义。
- `queryItemIds`（≤32）只是**声明**，运行时不对 `giveItem` 做白名单；但声明了非公开 ID 会让整包被拒。

## 11. 构建 / 校验 / 部署 / 发布

工程脚本（PowerShell，优先 pwsh7，UTF-8）：

```powershell
./tools/resolve-sdk.ps1   # 定位匹配 SDK
./tools/validate.ps1      # 调官方验证器，退出码 0 为通过
./tools/deploy.ps1        # 本地部署到 用户数据/mods（需完全重启）
./tools/publish.ps1       # 上传 Steam 创意工坊
```

本地 Mod 目录：`%APPDATA%\Pocket Cultivation Demo\mods\<mod-id>\`。
创意工坊用 steamcmd `workshop_build_item <workshop.vdf>`；VDF 关键字段：

```
"appid"           "4777710"
"publishedfileid" "<首次发布后回填，更新同一作品>"
"contentfolder"   "…\package\<mod-id>"        ← 指向成品目录本身
"previewfile"     "…\preview.png"             ← 新物品需要封面
"title" / "description" / "changenote"
```

## 12. 存档兼容

带脚本的包属 `ruleset`，绑定精确 ID/版本/内容哈希/domain 版本。给已有存档新增面板可能因兼容指纹变化被拒载；正式兼容升级需在 manifest 声明 `saveCompatibility`。所有脚本存档均为 `modded`，不参与官方成绩。

### 附：最小可用清单

1. `manifest.json`（modApiVersion 2 + maps + scripts）
2. `maps/anchor.json`（锚点，`officialBackgroundMapId` 省图）
3. `scripts/panel.json`（`ui.entry: menu`，`events: [interact, uiSubmitted]`）
4. `code/panel.js`（同步 handle + `panel.view`）
5. `tools/*`（校验/部署/发布）

照着第 4–6 节就能做出一个「加灵石 + 发指定道具」的最小面板；要覆盖全目录就加第 8–9 节的生成与分页搜索。
